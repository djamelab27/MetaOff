# MetaOff Privacy Policy

Effective date: September 1, 2026

MetaOff is designed so the developer does not receive user data.

## Data handled by the extension

When a user explicitly selects photos, MetaOff may read the selected files and metadata stored inside them, including location, timestamps, device details, descriptive text, author fields, and editing information. It uses this information only to show the local privacy scan and create cleaned copies requested by the user.

## Local processing

Selected files and scan results are processed in memory inside the user's browser. MetaOff does not upload, transmit, sell, share, or otherwise disclose them. It has no developer server, account system, advertising, analytics, telemetry, tracking pixels, or remote code.

MetaOff does not request Chrome storage permission. Closing or reloading the cleaner discards its in-memory queue. Cleaned files and optional reports are saved only when the user downloads them.

## Network access

MetaOff makes no network requests and requests no website access or host permissions.

## Retention

The developer retains no photo, metadata, filename, hash, scan result, or usage record because none is received. Browser-created temporary object URLs exist only during the open cleaning session and are revoked when items are cleared.

## User control

Users choose every file, can remove files from the queue before cleaning, and choose whether to preserve or remove embedded color profiles. Original files are never overwritten.

## Changes

Material changes to these practices will be documented in this file and in the extension's public listing before they take effect.

## Contact

Questions and security reports can be opened through the GitHub repository's issue tracker. Do not attach private photos to a public issue.
